# Secure File Manager CLI

Самостоятельный интерактивный файловый менеджер Windows на C#/.NET 9. Новый консольный интерфейс использует перенесённые Core, EF Core Data Layer и Windows-файловые адаптеры готового приложения. WPF, XAML и ViewModels в решение не входят. Исходный проект не нужен для сборки или запуска.

## Сборка и запуск

Требуются Windows, .NET SDK 9.0.200 (global.json), SQL Server Express с существующей SecureFileManagerDB и её актуальной схемой. Проверенная IDE: Visual Studio 2022 17.13.35818.85. Core/Data — net9.0; CLI/Windows/Tests — net9.0-windows. EF Core/SqlServer/Identity/DI остаются 9.0.22; обновление платформы не выполнялось.

```powershell
cd D:\SecureFileManager-CLI
dotnet build SecureFileManager-CLI.sln -c Debug
dotnet run --project src/SecureFileManager.Cli --launch-profile 'SecureFileManager CLI (Development)'
```

В Visual Studio откройте `SecureFileManager-CLI.sln`, назначьте `SecureFileManager.Cli` запускаемым проектом, выберите профиль `SecureFileManager CLI (Development)`, затем Ctrl+F5. Это обычное консольное приложение, Desktop Runtime для него не требуется.

Если Visual Studio сообщает, что библиотеку классов нельзя запустить напрямую: в «Обозревателе решений» нажмите правой кнопкой на **SecureFileManager.Cli** → **«Назначить запускаемым проектом»**, затем Ctrl+F5. Core/Data/Infrastructure являются библиотеками. CLI поставлен первым C#-проектом решения для первоначального выбора; уже сохранённый Visual Studio выбор нужно переключить вручную.

Локальный `src/SecureFileManager.Cli/appsettings.Development.json` уже скопирован из настроек WPF: Windows Authentication, локальный SQLEXPRESS, SecureFileManagerDB, фактический `D:\SecureFileManagerData\Storage`. Файл игнорируется Git. В Development для этого локального экземпляра явно сохранено существующее `TrustServerCertificate=True`; TLS включён, проверка подлинности сертификата отключена согласно прежней политике Development. Этот параметр не разрешён для удалённых серверов/Production.

На другой машине скопируйте `appsettings.example.json` в `appsettings.Development.json` и укажите свои существующие БД и StorageRoot. Пример требует доверенного сертификата. Development JSON копируется только в локальную сборку, в publish не включается. Не публикуйте локальные конфигурации и секреты.

Для явного конфигурирования и проверки без записи:

```powershell
$env:SFM_ENVIRONMENT = 'Development'
$env:SFM_CONFIG_DIRECTORY = (Resolve-Path src/SecureFileManager.Cli).Path
dotnet run --project src/SecureFileManager.Cli --no-launch-profile -- --check
dotnet run --project src/SecureFileManager.Cli --no-launch-profile
```

`--help` показывает параметры без подключения; `--check` выполняет только чтение SQL/метаданных/каталогов, без аудита, создания каталогов, синхронизации и восстановления. Несовместимая схема или неверные каталоги пользователей блокируют меню. Расхождения отдельных Files показываются предупреждением, сохраняя доступ к явному восстановлению после входа. Код возврата: 0 — проверка пройдена (возможны предупреждения), 2 — проверка не пройдена, 1 — ошибка конфигурации/выполнения.

Конфигурация прежняя: `SFM_ENVIRONMENT` = Production по умолчанию или Development; `SFM_CONFIG_DIRECTORY` — каталог JSON (по умолчанию рядом с exe). Production читает `appsettings.json`, Development — `appsettings.Development.json`. `SFM_CONNECTION_STRING` переопределяет подключение, `SFM_STORAGE_ROOT` — StorageRoot. Перед запуском проверьте старые переменные окружения: они имеют приоритет над JSON. SQL и хранилище не копируются в репозиторий.

## Использование

Начальное меню: регистрация, вход, выход. После входа: диски/каталоги, личные файлы, документы, ZIP, журнал, настройки, выход из аккаунта/программы. Пароль вводится звёздочками, Backspace удаляет символ, Esc отменяет. Пароль через перенаправленный stdin не принимается. Русский текст выводится в UTF-8.

`0` возвращает из раздела, `/cancel` отменяет текущий ввод. Объекты выбираются по номеру таблицы. Есть текущий путь, поиск по имени, сортировка по имени/размеру/дате, просмотр свойств. Ctrl+C запрашивает отмену выполняемой сервисной операции; CLI дожидается результата и компенсации. В меню используйте 0 для выхода.

В «Мои файлы» доступны создание папок/TXT/JSON/XML, открытие, импорт, удаление с подтверждением, явная сверка метаданных, восстановление незавершённых операций, ZIP. Личное удаление сохраняет прежнюю семантику: soft-delete метаданных и физическое удаление после подтверждения; пользовательской корзины личных файлов в исходном IFileService нет. Копирование, перемещение и переименование личных объектов не добавлялись: этих команд нет в исходном контракте.

Во внешних каталогах доступны прежние просмотр/создание/копирование деревьев/перемещение в пределах тома/переименование, редактор TXT/JSON/XML, корзина приложения, восстановление и ZIP. Восстановление запрашивает **полный исходный путь**; он доступен в журнале. Корзина — прежние `.sfm-trash-*` на исходном томе и проверенные квитанции, не Windows Recycle Bin. Она не освобождает место. Обход Windows ACL, overwrite и merge отсутствуют.

Редактор: просмотр, изменение существующих строк, вставка/удаление строк, замена фрагмента, валидация, сохранение, перечитывание и отмена изменений. Пункт **2 «Редактировать строку»** показывает номера строк и подставляет выбранную строку для изменения: используйте ←/→, Home/End, Backspace/Delete; Enter принимает изменение. Пункт 8 вставляет строку, 9 удаляет с подтверждением, 10 заменяет все точные совпадения фрагмента с учётом регистра. Нетронутые строки и их исходные переводы строк сохраняются.

Полная замена вынесена в пункт **7**: введите строки до `.end`; `/cancel` сохраняет старый буфер. Новые строки при полной замене соединяются CRLF без завершающего перевода строки. Существующий BOM сохраняет адаптер. Изменения буфера записываются только пунктом 4 или после выбора сохранения при закрытии. При конфликте буфер остаётся. Завершение терминала/EOF не может сохранить несохранённый буфер автоматически.

Интерактивный ввод/вывод Windows использует ReadConsoleW/WriteConsoleW (Unicode), поэтому кириллица не проходит через OEM-кодовую страницу консоли. При перенаправлении stdin/stdout сохраняется UTF-8. Уже сохранённый текст со знаками `�` автоматически восстановить нельзя: правильный текст нужно ввести повторно или восстановить из своей копии.

Текст ограничен 10 МиБ, импорт 100 МиБ. ZIP использует прежний ZipEngine: 250 записей, 25 МиБ/файл, 100 МиБ распакованных данных, ratio 100:1, проверки путей/CRC/фактических байтов. Создание Store, чтение Store/Deflate; ZIP64/encryption/multipart не поддерживаются. YAML отсутствует.

## Общие данные WPF и CLI

CLI и WPF могут использовать **одну SecureFileManagerDB и один StorageRoot**. Сохраняются GUID пользователей, IdentityV3-хеши, lockout, таблицы Users/Files/ExternalDocuments/Operations, миграции, UserId-каталоги и служебные планы. CLI не создаёт вторую БД или копию хранилища. При входе существующий каталог только проверяется; регистрация нового пользователя выполняет прежний RegistrationService.

Рекомендуемый режим — последовательные сеансы: завершить WPF → CLI → завершить CLI → WPF и обновить список. Одновременная работа двух процессов **не сертифицирована**. SQL Serializable/UPDLOCK, файловые lock/pins и версии сохранены, но они не дают общей атомарности SQL+NTFS и не заменяют приёмку двух процессов. Подробности — [ARCHITECTURE](docs/ARCHITECTURE.md).

Запуск проверяет миграции, столбцы, ключи/индексы/ограничения и наличие каталогов пользователей/учтённых объектов. Нет исходной криптографической привязки БД к StorageRoot: совпавшие GUID/пути/размеры не доказывают подлинность копии. БД без существующего `StorageRoot/Users` не инициализируется автоматически. При предупреждении Files сначала перепроверьте конфигурацию; диагностика и восстановление доступны после входа. Если список заблокирован pending-операцией, раздел «Мои файлы» предложит явное восстановление до загрузки списка. CLI ничего не ремонтирует при запуске. Проверка ограничена 10000 пользователями/активными объектами.

Не запускайте миграции, EnsureCreated/EnsureDeleted, очистку таблиц или восстановление над рабочими данными как часть установки CLI. В коде CLI таких вызовов нет. Исходные миграции сохранены для совместимости и создания **изолированных тестовых** баз.

## Проверки

```powershell
./scripts/Test-CLI.ps1                 # без SQL, интеграционные тесты пропускаются
./scripts/Test-CLI.ps1 -Sql            # новые GUID-базы, нужны CREATE/DROP DATABASE права
./scripts/Test-CLI.ps1 -Sql -Configuration Release
```

SQL fixture запрещает существующую тестовую БД, проверяет отсутствие сгенерированного имени и удаляет только созданную им БД. Используются временные файловые каталоги; файлы оставлены для диагностики, не очищайте их рекурсивно без проверки ссылок/границ. Скрипт восстанавливает окружение. TRX — в `artifacts/tests`.
