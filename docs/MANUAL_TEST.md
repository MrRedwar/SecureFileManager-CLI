# Ручная приёмка

Автоматические тесты используют отдельные данные. Следующие действия выполняет пользователь осознанно; работа с существующим аккаунтом через сервисы добавляет записи аудита и может менять выбранные файлы. Не используйте ценные документы для проверки удаления/редактирования. Не удаляйте рабочую БД или `.sfm-*` вручную.

1. Соберите solution, запустите `--help`, затем `--check` с собственным CLI-конфигом. Проверьте правильность SQL/StorageRoot и успешное сообщение. При неверном root/сервере должен быть отказ без создания новой папки/БД. Верните конфигурацию.
2. Завершите сеанс WPF. Запустите CLI в Windows Terminal/консоли Visual Studio. Проверьте кириллицу, звёздочки вместо пароля, Backspace, Esc, /cancel, неверный пункт, пустой ввод, неверный номер. Реальный keyboard/TTY пока отдельно не подтверждён.
3. Войдите под ранее созданным в WPF аккаунтом. Убедитесь, что видны прежние личные файлы и используется прежний GUID-каталог, новый не появился. Проверяйте неверный пароль только осознанно: прежний lockout действует.
4. На тестовом аккаунте создайте папку и TXT/JSON/XML. В редакторе замените текст, завершите `.end`, проверьте валидацию и сохранение; ошибочные JSON/XML не должны сохраняться. Проверьте отмену буфера и закрытие с Save/Discard/Continue. Неподдерживаемый бинарный файл не должен читаться редактором.
5. Откройте один документ в CLI и измените его другим разрешённым процессом на тестовых данных. Сохранение устаревшей версии должно дать конфликт с сохранением CLI-буфера. Перечитывание — после подтверждения. Полную одновременную эксплуатацию WPF+CLI это не сертифицирует.
6. Импортируйте собственный внешний тестовый файл в личную папку. Удалите только тестовый объект с подтверждением. Личное удаление не имеет пользовательского Restore. Отмена подтверждения не меняет объект.
7. В «Диски и каталоги» проверьте свойства дисков, переход по адресу, вверх, свойства объектов, поиск/сортировку. Попытка открыть личный Storage через внешний режим должна отклоняться. Не проверяйте обход ACL повышением прав.
8. Во временном внешнем каталоге создайте TXT/JSON/XML/папку, скопируйте дерево с пустой папкой, переименуйте и переместите в пределах тома. Существующее имя назначения не должно перезаписываться. Move между томами должен явно отклоняться, copy доступен в прежних лимитах.
9. Отправьте только внешний тестовый объект в корзину приложения. По исходному полному пути восстановите его. Занятый путь не должен перезаписываться. Не очищайте скрытые корзины вручную; место не освобождается.
10. Создайте ZIP, посмотрите состав, распакуйте в новую папку; проверьте private и external режимы. Не используйте опасные архивы на рабочих данных: негативные ZIP тесты уже изолированы. На достаточно длительной тестовой операции нажмите Ctrl+C; дождитесь результата/rollback, проверьте журнал и отсутствие частичного опубликованного дерева.
11. Проверьте фильтры/страницы журнала и только собственные события. В настройках проверьте audit probe и диагностику. При предупреждении preflight о Files сначала проверьте правильность StorageRoot. Явное восстановление запускайте только при известной незавершённой операции и доступной SQL; не удаляйте планы. Если pending блокирует сам список личных файлов, меню должно предложить восстановление до его загрузки.
12. Выйдите из CLI, затем откройте WPF под тем же аккаунтом, обновите список и журнал: новые тестовые документы/изменения/Operations должны отображаться. Повторите с другим аккаунтом: личные данные первого не доступны. Внешние каталоги доступны по общим Windows ACL согласно исходной модели.
13. Проверьте published папку без исходного проекта и локального конфига из build: задайте внешний конфиг и запустите exe. Для чистой установки нужны существующая совместимая SQL-база и правильный StorageRoot; CLI не разворачивает БД автоматически.

Фиксируйте дату, сборку, шаги, ожидаемый/фактический результат, сохраняя секреты вне отчёта. Физические removable media/disk full/power loss, закрытие терминала во время записи и межпроцессная recovery-матрица остаются отдельной приёмкой на изолированных данных.
